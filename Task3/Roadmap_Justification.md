# Обоснование этапов роадмапа

Роадмап трансформации IT-ландшафта «Будущее 2.0» разбит на пять этапов, каждый из которых направлен на достижение конкретных бизнес-целей. Ниже приведено обоснование каждого этапа, ожидаемые результаты, ответственные команды и необходимые ресурсы.

## Общие принципы последовательности этапов

1. **Сначала фундамент, потом функциональность** – на этапе 0 создаётся скелет платформы (Camel, Kafka, S3, Flink), без которого невозможны последующие интеграции.
2. **От критичных к менее критичным доменам** – сначала подключаются домены, наиболее важные для выручки и комплаенса (MDM, биллинг, финтех).
3. **Постепенное наращивание сложности** – после запуска базовых витрин добавляются продвинутые функции (Data Quality, семантический слой, CI/CD).
4. **Параллельная работа над безопасностью и наблюдаемостью** – задачи безопасности (De‑ID, токенизация) начинаются с самого начала и продолжаются на всех этапах.

## Детализация этапов

### Этап 0: Скелет платформы и безопасность (январь – апрель 2026)

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Обеспечить технологическую основу для быстрой интеграции доменов и гарантировать безопасность данных (PHI) с первого дня. |
| **Почему именно сейчас** | Без работающей шины событий (Kafka) и интеграционного слоя (Camel) невозможно начать миграцию доменов. Без De‑ID/токенизации нельзя обрабатывать медицинские данные, что блокирует развитие ИИ-направлений. |
| **Ожидаемые результаты** | 1. Готовая к работе платформа: Camel, Kafka, S3, Flink.<br>2. Настроенная Kafka Schema Registry для управления контрактами.<br>3. Запущен сервис De‑ID/токенизации, позволяющий безопасно использовать PHI для ИИ и аналитики. |
| **Ответственные команды** | Команда платформы данных, команда безопасности, DevOps. |
| **Необходимые ресурсы** | 3–5 инженеров данных, 2 инженера безопасности, облачная инфраструктура (VM, managed Kafka, object storage). |

### Этап 1: Подключение ключевых доменов и первые витрины (февраль – июль 2026)

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Запустить витрины данных для критичных бизнес-процессов (биллинг, финансы, платежи) и обеспечить самообслуживание аналитиков. |
| **Почему именно сейчас** | После готовности платформы можно начать миграцию наиболее болезненных точек – биллинга и финансов, от которых зависит выручка и операционная эффективность. |
| **Ожидаемые результаты** | 1. Подключены домены: MDM, биллинг, финтех-платежи.<br>2. Работающие витрины в ClickHouse, доступные через Superset/Portal MVP.<br>3. Перенос отчётности Power BI на ClickHouse (частичный).<br>4. Базовые проверки качества данных во Flink. |
| **Ответственные команды** | Команды доменов (биллинг, финансы, финтех), команда платформы данных, аналитики. |
| **Необходимые ресурсы** | 4–6 разработчиков доменов, 2–3 инженера данных, лицензии Superset, дополнительные мощности ClickHouse. |

### Этап 2: Онбординг остальных доменов и партнёров (июль – октябрь 2026)

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Расширить экосистему за счёт подключения клинических операций, инвентаря, кредитного домена и внешних партнёров (фарма, электроника). |
| **Почему именно сейчас** | После отладки процессов на ключевых доменах можно масштабировать модель на остальные направления, что ускоряет интеграцию новых бизнесов. |
| **Ожидаемые результаты** | 1. Подключены домены: клинические операции, инвентарь, кредитный домен.<br>2. Налажены потоки данных с партнёрами через Camel → Kafka → Flink → ClickHouse.<br>3. Специализированные витрины для кредитного конвейера. |
| **Ответственные команды** | Команды клиники, инвентаря, кредитного подразделения, партнёрский отдел, платформа данных. |
| **Необходимые ресурсы** | 5–7 разработчиков доменов, 2 инженера интеграций, дополнительные брокеры Kafka, мониторинг. |

### Этап 3: Углубление качества данных и автоматизация (сентябрь – декабрь 2026)

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Повысить доверие к данным за счёт внедрения семантического слоя, усиления проверок качества и автоматизации развёртывания пайплайнов. |
| **Почему именно сейчас** | Когда количество витрин и доменов растёт, ручное управление качеством и метриками становится непосильным; автоматизация и стандартизация необходимы для дальнейшего масштабирования. |
| **Ожидаемые результаты** | 1. Семантический слой (Cube/MetricFlow) для ключевых KPI.<br>2. Расширенные проверки Data Quality во Flink.<br>3. CI/CD для данных (автотесты схем, развёртывание джобов).<br>4. Усиление ABAC/RBAC для тонкого управления доступом. |
| **Ответственные команды** | Команда качества данных, команда DevOps данных, архитекторы. |
| **Необходимые ресурсы** | 2–3 инженера качества данных, 2 инженера DevOps, инструменты семантического слоя (Cube), вычислительные ресурсы для тестов. |

### Этап 4: Оптимизация и масштабирование (ноябрь 2026 – март 2027)

| Аспект | Описание |
|--------|----------|
| **Бизнес-цель** | Достичь максимальной производительности и отказоустойчивости платформы, завершить перенос всей критичной отчётности с DWH, предоставить бизнесу полнофункциональный портал самообслуживания. |
| **Почему именно сейчас** | После того как все домены подключены и качество данных обеспечено, можно сосредоточиться на оптимизации затрат и улучшении пользовательского опыта. |
| **Ожидаемые результаты** | 1. Портал самообслуживания с расширенными функциями (роли, алёрты, конструктор дашбордов).<br>2. Оптимизированные кластеры ClickHouse (улучшение производительности запросов).<br>3. Масштабирование кластеров Apache Flink и Kafka для обработки возросшей нагрузки.<br>4. Полный перенос критичной отчётности Power BI на ClickHouse. |
| **Ответственные команды** | Команда платформы данных, команда BI, команда эксплуатации. |
| **Необходимые ресурсы** | 3–5 инженеров данных, 2 администратора БД, дополнительные вычислительные ресурсы для масштабирования, лицензии портала (если требуется). |

## Связь с бизнес-сценариями

Каждый этап напрямую поддерживает ключевые бизнес-сценарии компании:

- **Быстрая подготовка отчётности** – этапы 1, 2, 4 (витрины ClickHouse, портал самообслуживания).
- **Независимое развитие финтех- и ИИ-направлений** – этапы 0, 1, 2 (событийная шина, De‑ID, отдельные домены).
- **Масштабирование для новых бизнесов** – этапы 2, 4 (подключение партнёров, масштабирование кластеров).
- **Соблюдение регуляторных требований** – этапы 0, 3 (безопасность PHI, управление доступом).
- **Повышение операционной эффективности** – все этапы (автоматизация, качество данных, мониторинг).

Таким образом, предложенная последовательность этапов обеспечивает постепенное, управляемое преобразование IT-ландшафта с минимальными рисками для бизнеса и максимальным возвратом инвестиций на каждом шаге.
